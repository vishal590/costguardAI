# Cross-Account Role Setup Guide

This guide explains how to set up cross-account IAM roles in member accounts to allow CostGuard AI to collect cost data.

## Overview

CostGuard AI uses AWS STS AssumeRole to securely access cost data from member accounts. Each member account needs an IAM role with:
- Read-only permissions for Cost Explorer API
- Read-only permissions for CloudWatch metrics
- Trust policy allowing the management account to assume the role
- External ID for additional security

## Prerequisites

- AWS Organizations enabled in your management account
- Access to deploy CloudFormation stacks in member accounts
- Management account ID where CostGuard AI is deployed
- External ID (generated by CostGuard AI or use a secure random string)

## Deployment Methods

### Method 1: Manual Deployment (Single Account)

1. **Get your Management Account ID**
   ```bash
   aws sts get-caller-identity --query Account --output text
   ```

2. **Generate or obtain External ID**
   - Use a secure random string (8-64 characters)
   - Example: `CostGuard-2024-abc123xyz`

3. **Deploy CloudFormation Stack**
   ```bash
   aws cloudformation create-stack \
     --stack-name CostGuardCollectorRole \
     --template-body file://cross_account_role_template.yaml \
     --parameters \
       ParameterKey=ManagementAccountId,ParameterValue=123456789012 \
       ParameterKey=ExternalId,ParameterValue=YOUR_EXTERNAL_ID \
     --capabilities CAPABILITY_NAMED_IAM \
     --region us-east-1
   ```

4. **Verify Deployment**
   ```bash
   aws cloudformation describe-stacks \
     --stack-name CostGuardCollectorRole \
     --query 'Stacks[0].StackStatus' \
     --output text
   ```

5. **Get Role ARN**
   ```bash
   aws cloudformation describe-stacks \
     --stack-name CostGuardCollectorRole \
     --query 'Stacks[0].Outputs[?OutputKey==`RoleArn`].OutputValue' \
     --output text
   ```

### Method 2: StackSets (Multiple Accounts)

For deploying to multiple accounts simultaneously:

1. **Create StackSet in Management Account**
   ```bash
   aws cloudformation create-stack-set \
     --stack-set-name CostGuardCollectorRoleStackSet \
     --template-body file://cross_account_role_template.yaml \
     --parameters \
       ParameterKey=ManagementAccountId,ParameterValue=123456789012 \
       ParameterKey=ExternalId,ParameterValue=YOUR_EXTERNAL_ID \
     --capabilities CAPABILITY_NAMED_IAM \
     --permission-model SERVICE_MANAGED \
     --auto-deployment Enabled=true,RetainStacksOnAccountRemoval=false
   ```

2. **Deploy to Organizational Units**
   ```bash
   aws cloudformation create-stack-instances \
     --stack-set-name CostGuardCollectorRoleStackSet \
     --deployment-targets OrganizationalUnitIds=ou-xxxx-yyyyyyyy \
     --regions us-east-1
   ```

3. **Monitor Deployment**
   ```bash
   aws cloudformation list-stack-instances \
     --stack-set-name CostGuardCollectorRoleStackSet
   ```

### Method 3: AWS Console

1. Navigate to CloudFormation in the member account
2. Click "Create stack" → "With new resources"
3. Upload `cross_account_role_template.yaml`
4. Enter parameters:
   - ManagementAccountId: Your management account ID
   - ExternalId: Your secure external ID
5. Acknowledge IAM resource creation
6. Click "Create stack"

## Security Best Practices

### External ID
- Use a unique, random external ID for each organization
- Store the external ID securely (e.g., AWS Secrets Manager)
- Never commit external IDs to version control
- Rotate external IDs periodically (requires role update)

### Least Privilege
The role template follows least privilege principles:
- Read-only access to Cost Explorer
- Read-only access to CloudWatch metrics
- No write permissions
- No access to other AWS services

### Session Duration
- Default: 1 hour (3600 seconds)
- Credentials automatically expire
- CostGuard AI requests new credentials as needed

## Verification

After deployment, verify the role works:

```bash
# From management account
aws sts assume-role \
  --role-arn arn:aws:iam::MEMBER_ACCOUNT_ID:role/CostGuardCollectorRole \
  --role-session-name test-session \
  --external-id YOUR_EXTERNAL_ID
```

Expected output: Temporary credentials (AccessKeyId, SecretAccessKey, SessionToken)

## Troubleshooting

### Error: "User is not authorized to perform: sts:AssumeRole"
- Verify the management account ID in the trust policy
- Check that the external ID matches
- Ensure the role exists in the member account

### Error: "Role does not exist"
- Verify CloudFormation stack deployed successfully
- Check the role name is exactly "CostGuardCollectorRole"
- Ensure you're in the correct AWS region

### Error: "Access Denied" when calling Cost Explorer
- Verify the role has the CostGuardCostExplorerAccess policy
- Check that Cost Explorer is enabled in the member account
- Ensure the account has cost data available

## Cleanup

To remove the role from a member account:

```bash
aws cloudformation delete-stack \
  --stack-name CostGuardCollectorRole
```

For StackSets:

```bash
# Delete stack instances first
aws cloudformation delete-stack-instances \
  --stack-set-name CostGuardCollectorRoleStackSet \
  --accounts ACCOUNT_ID_1 ACCOUNT_ID_2 \
  --regions us-east-1 \
  --no-retain-stacks

# Then delete the StackSet
aws cloudformation delete-stack-set \
  --stack-set-name CostGuardCollectorRoleStackSet
```

## Integration with CostGuard AI

Once roles are deployed, configure CostGuard AI:

1. Store the external ID in the management account
2. Run organization discovery to find all member accounts
3. CostGuard AI will automatically attempt to assume roles
4. Failed role assumptions are logged for troubleshooting
