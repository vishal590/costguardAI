# Workload declarations and GPU-pattern observations

Current local source contract, October 14, 2026; tasks 176-179. Supersedes older automatic-classification, numeric-confidence and unversioned-write examples. All testing, builds, browser checks, deployment and account validation remain deferred.

## Read declarations

`GET /api/ai-ml/workload-classification?instance_id=i-0123456789abcdef0&mode=manual_only` returns `data_contract=workload_label_observations_v2` and `manual_label` with instance ID, version, application override, effective label/source and unavailable confidence. No metric dates are needed. Active application declarations precede valid nonconflicting EC2 `WorkloadType` tags (case/hyphen/underscore normalized). Invalid or conflicting tags produce unknown. Missing application rows have version 0. Storage/read failures return 503, never a fabricated empty label.

Labels training/inference/idle are operator assertions, not independently verified workload identity, billing attribution or permission to stop resources. Reads use the configured account and SDK region; they do not search other accounts/regions. An application declaration can outlive the resource; reads with an active override do not revalidate live existence, while writes resolve current instance metadata first.

## Write or clear declarations

Operator/admin POST to the same route accepts JSON `instance_id`, `expected_version` from the current read and optional text `reason` (at most 1024 characters). Default `operation=set` also requires `workload_type` training/inference/idle. `operation=clear` must omit `workload_type`; it disables the application override and returns to tag/unknown source. Clear changes application metadata only and does not delete EC2 tags. Unknown fields/invalid inputs return 400, stale versions return 409 and unavailable storage/readback returns 503. On an uncertain outcome, refresh before retrying. Authentication supplies the actor; the caller cannot choose it.

Consistent reads and conditional writes increment the version, including clear. The retained `date=MANUAL` pointer is never deleted or assigned TTL, preventing revision reuse. The frontend loads current state before edits, blocks known stale drafts, permits explicit draft reload and uses server invalidation after writes. A later writer can change state again; a successful response is not a lock on future declarations.

## Assess metric patterns

GET with default `mode=assessment` additionally requires start_date/end_date covering 1-31 completed UTC dates (exclusive end). Response `classification_observations_v2` separates manual source from utilization pattern and data quality. It uses configured complete hourly all-device GPU maxima; no CPU substitution or missing-as-zero occurs. Patterns `low_hourly_maxima`, `sustained_high_hourly_maxima`, `mixed_or_midrange_hourly_maxima` describe numeric observations only. Missing configuration/evidence returns unavailable pattern and null average. Workload identity and calibrated confidence remain unverified/null. Assessment never persists an inferred label.

See [GPU evidence contracts](gpu-observed-contracts.md) for operator metric configuration and source limitations.

## Retained declaration changes (tasks 186-187)

Set/clear now writes both the MANUAL pointer and `date=HISTORY#` plus a 16-digit zero-padded new version, in one DynamoDB transaction. History kind is manual_workload_label_change, schema 2, with previous_version, set/clear operation, nullable declaration, authenticated actor, reason, UTC updated_at and observed region. Neither row has TTL. A conditional collision aborts the transaction and returns conflict when the service supplies a conditional-cancellation reason; other transaction/storage failures remain unavailable. This is application-retained history, not tamper-proof storage or complete tag/resource audit evidence. Existing historical rows are not backfilled. Storage grows with future writes; retention policy is deferred and no history is deleted by these APIs.

`GET /api/ai-ml/workload-classification?instance_id=i-0123456789abcdef0&mode=history` returns workload_label_history_v2 with history.instance_id, current_pointer_version, changes, has_more, next_before_version and explicit legacy-history gaps. Optional positive safe-integer before_version requests strictly older revisions. Dates are forbidden in history mode, and before_version is forbidden in other modes. Reads use consistent pointer/query observations and cap the query at the observed pointer version; multiple pages are not a locked snapshot. Twenty newest-first rows are returned per page. Invalid stored rows/storage errors fail unavailable rather than silently disappearing. An empty retained page does not establish no earlier changes. Frontend inspects actor/time/reason/region and set/clear operations, using server invalidation after writes.

Transactional Put permissions are governed by the existing underlying PutItem permission; no new cloud operation or deployment was performed. [AWS transaction IAM guidance](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/transaction-apis-iam.html). All testing/build/browser/account/deployment validation remains deferred.

Task 188 exports only the current retained history page with pointer/page/scope/legacy-gap fields. Shared CSV cell encoding escapes spreadsheet formula prefixes; it does not establish historical completeness. Validation deferred.

Task 205 scopes declaration set/clear invalidation to the selected instance across manual/history/assessment reads, including uncertain writes, while retaining unrelated billing reports. Read-only GPU previews persist no action and invalidate no reports. Strict query parsing is shared with public audit selections; classification retains its 128-character value bound and mode rules. Validation deferred.

Task 220 adds POST write_observation.committed_version, operation and readback_at_committed_version. The conditional transaction commits exactly expected_version+1, but a consistent readback may already show another actor's newer declaration. UI binds its saved draft to the acknowledged committed revision, never silently adopting a newer readback revision for an older draft. A later read remains stale until explicit current-declaration reload; CAS remains authoritative even before UI notices a concurrent write. A failed readback still returns unavailable and callers refresh before retrying. Validation remains deferred.

If an older/malformed write response lacks a valid committed-version acknowledgement, the editor warns that the write may already have succeeded and asks the operator to refresh/use current state before retrying. It does not silently bind the draft to an unacknowledged version. Backend version conditions remain the final conflict guard. Validation deferred.
