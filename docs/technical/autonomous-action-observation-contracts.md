# Autonomous recorded-outcome observations

Current local source, October 14, 2026, tasks 216-219. All tests/builds/compilation/synthesis/browser/account/deployment validation remain deferred. Existing worker execution, approval, rollback and training flows are not enabled or invoked by this work.

The existing GET /api/autonomous/confidence-scores now returns data_contract autonomous_action_observations_v2. No query parameters are accepted. It observes stored completed action records; it does not query a calibrated learning model or independently verify business/resource outcomes. The compatibility confidence_scores map contains per-type record statistics, not calibrated confidence.

At most ten scan pages with Limit 100 are inspected. Projection includes identifiers/type/status, explicit outcome/score/TTL and declared demo flags, including only the relevant nested parameter flags rather than full action parameters. Completed filtering applies after storage items are evaluated, so empty matched pages may still continue. Scans are not locked snapshots and missing recent writes are possible. [AWS Scan semantics](https://docs.aws.amazon.com/amazondynamodb/latest/APIReference/API_Scan.html).

Data quality reports page limits/read count, scanned_rows (null if unavailable), returned completed rows, invalid/expired/unknown-retention/duplicate rows, conflicting identities, retained unique records and remaining cursor scope. Known expired TTL rows are excluded; missing/invalid TTL is explicitly unknown retention, not a verified reporting period. Duplicate action-ID/timestamp observations are deduplicated; conflicting observations omit that identity. Further stored rows outside bounds are not inspected. Storage/source failure returns 503, not an empty-success report. Timestamp is aware UTC read completion.

Per type, total_actions counts retained completed records. Successful/failed counts require explicit stored booleans; an existing invalid success field cannot be overridden by legacy outcome text. When success is absent, exact legacy success/failure labels are accepted as stored assertions. Other outcomes remain unknown. success_rate divides stored successful by known_outcome_actions only; it is null when no outcomes are known. Because the sample is completed records only, this is not an overall execution/job success rate and excludes noncompleted failures from its cohort.

avg_confidence is null and confidence_method unavailable. recorded_score_average/count summarize only finite stored heuristic values in [0,1], with separate missing/invalid counts. No default 0.5, missing-as-zero or calibrated probability is fabricated. Declared demo/non-demo/unknown-or-conflicting counts use explicit consistent booleans; invalid/conflicting/missing flags remain unknown, and non-demo does not establish verified production scope. Execution verification and calibrated confidence remain false.

The existing demo statistics tab now uses currentData and the new contract, separates known/unknown outcomes from recorded heuristics and unavailable calibrated confidence, and shows scan/retention/conflict gaps. It refreshes on demand rather than polling an expensive scan every five seconds. Existing autonomous mutation invalidation can still refresh mounted data. The first 50 returned action types display; CSV includes every returned type summary, denominators, declared scope and source/read/verification flags. It does not export underlying action rows or prove complete history. Core demo run/action/approval/rollback forms remain in place. Actual UI/download validation remains deferred.
