# Direct known-resource inspection

Current local source, October 14, 2026, tasks 213-214. No tests/builds/compilation/synthesis/browser/account calls or deployment validation ran. All remain deferred.

GET /api/prevention/resource?service=ec2&resource_id=i-0123456789abcdef0 directly reads one configured EC2/RDS/Lambda resource, independent of bounded inventory listing. service and resource_id are required single-valued bounded text; unknown/repeated/conflicting query representations return 400. The selected service must be enabled in monitoring discovery configuration. The route uses the existing main API/BFF account authorization and SDK region; callers cannot select another account/region or supply an ARN/alias/version.

EC2 accepts a bare instance ID (legacy eight or current seventeen lowercase hexadecimal suffix). RDS accepts a bare instance name, starts with a letter, at most 63 letters/digits/hyphens, without doubled/trailing hyphens; lookup normalizes its case. Lambda accepts an unqualified bare function name of at most 64 letters/digits/underscore/hyphen. These are the implemented input constraints, not a claim to support all provider identifier forms. Direct reads use describe_instances(InstanceIds), describe_db_instances(DBInstanceIdentifier) or get_function(FunctionName); no listing pages, inventory puts, CloudWatch metrics, billing reads or resource actions are invoked by this inspection path. Initial configuration still uses the existing durable configuration read. Other page components may separately request inventory.

Response data_contract resource_inspection_observations_v2 includes resource, observed_at, applied_selection and data_quality. Metadata must resolve to exactly one matching identity in the SDK client's region. Provider denial/not-found/outage or ambiguous/malformed observations return 503 unavailable, not a fabricated empty resource or verified absence. Oversized metadata returns 413 at 256 KiB. As with other discovery observations, configured backend account is not independently verified by STS. Metadata does not verify budget membership, protected-tag coverage, idleness, monetary cost or action eligibility; those remain false/unavailable. No automatic action or inventory persistence is added.

Resource objects retain the same raw identifiers and selected metadata as discovery: EC2 state/type/profile/root/last-launch information, RDS state/creation/engine/topology fields, Lambda function ARN/name/state/last-modified and returned tags. EC2 launch and Lambda modification are not creation dates. Shared Lambda metadata conversion is used by direct and listed reads.

The Resources view adds explicit service/ID selection with current-query guards and refresh. It displays returned tags/properties and permits JSON export only for the current observation. Export data_contract resource_inspection_export_v1 carries export time separately from backend observation time, applied selection, resource and quality. No whole-inventory, billing or eligibility guarantee is implied. Bounded listing resources outside the current selection can be looked up by known ID through this path, but resource-list pagination remains unavailable. Browser/download and deployment validation are deferred.
