# Advisor evidence and prompt boundaries

Current local source changes, October 14, 2026, tasks 189-197 and 204. All tests, builds, compilation, browser checks, account calls and deployment validation remain deferred.

The main advisor uses ContextManager, AdvisorEngine and BedrockAdvisorClient. The separate AI/ML advisor integration module is not wired into this path. GPU patterns, versioned declarations and new history views do not automatically become main-advisor context.

Questions must be nonempty text of at most 2000 characters. UI shows the bound; API rejects invalid input with 400 before starting its advisor worker. Prompt construction independently enforces it. An 8000-character budget preserves the full current question and fixed evidence/uncertainty instructions. Whole optional blocks are included only when they fit; omissions have a marker. Character counts do not guarantee token counts or provider limits. History excerpts are bounded to three turns and explicitly potentially stale.

Historical monetary summaries use finite observed USD BlendedCost values for up to five services, with other-service omission counts; partial/invalid rows do not produce a complete subtotal. Observed rows do not verify invoice or date completeness. Forecast summaries use supplied nonnegative finite points and never zero-fill missing amounts. Forecast uncertainty remains uncalibrated. Prevention record estimates are unverified, potentially overlapping projections, with known/missing counts. When all are missing, the amount stays unavailable. Known estimate subtotals never establish total opportunity or realized savings. USD budget fields require valid finite amounts; missing/unsupported values remain unavailable.

Availability context preserves selected status/metric/period fields and date counts with the first five dates, explicitly indicating truncated date lists. Model text remains unverified advice and must not invent amounts, workload identity or confidence. These prompt rules improve supplied evidence; they do not independently validate generated answers or prevent all prompt injection. Existing response formatting, authorization, session ownership and execution boundaries remain in effect.

The advisor cache namespace advances to advisor-context-v4-evidence-metadata while retaining existing owner/session/revision/history/query identity. Earlier answers generated under previous prompt rules are not reused under this key. Source only; no model inference or deployment was performed.

Tasks 192-195 extend these boundaries. Descriptive anomaly flags consistently use finite USD BlendedCost rows with unique valid dates and at least three samples, compared against sample mean plus/minus two sample standard deviations. Missing rows are not filled, uniform samples produce no arbitrary flags, and no flag establishes normal spending or complete analysis. The method is not a calibrated probability or billing-error detector.

`cost_data.evidence` with data_contract advisor_evidence_context_v2 carries request-local prepared_at, prompt character count/limit, question count/preservation, optional/included/omitted block counts, context_omitted, historical service counts/summary limit/omissions, compact data_availability and false model/estimate/date-and-invoice verification flags. The existing answer cache preserves the original metadata; cached counts/time describe the original answer context. Frontend explains unavailable details for older contracts. No shared mutable prompt report is used.

Response cost tables preserve unknown values and unsupported currencies, label known observed subtotals separately from unavailable full returned subtotals, retain credits and expose omitted service-row counts. A positive fully available returned subtotal is required for shares; no account invoice completeness is inferred.

Advice extraction does not treat nearby currency amounts as savings or presume action safety/priority. Those fields are null with explicit unavailable bases in the API. The main formatter still returns no structured recommendations; changing the separate parser does not imply it has been wired into the main advisor. Frontend does not default missing savings to zero. All validation remains deferred.

Tasks 196-197 add request-local data_availability.anomaly_observations and prevention_observations, retained in cached answer evidence. Comparison quality includes considered/analyzed/skipped services, reason counts, returned flags and explicit uncalibrated/incomplete scope. UI exposes analyzed/skipped counts without treating no flags as normal spending.

Advisor prevention context scans at most ten pages with Limit 100, retaining at most 100 matching records. It uses aware timestamps and an exclusive end, excludes pre-action/rollback records, counts invalid records and matching omissions, and discloses remaining provider cursors. The selection is not ordered by newest before scanning, so it is not the latest 100 actions or a complete inventory. No returned cursor does not eliminate invalid/omitted rows. Resource/action text is bounded; missing/invalid/negative estimate values remain unavailable. Record success is a stored assertion, not independently verified execution or savings. Failures return no partial action list and mark the quality unavailable; not-configured/not-requested states remain distinct. Page limits do not bound SDK retries or guarantee request deadlines. Validation remains deferred.

Export time does not refresh source evidence. It includes no new model/account/resource operation. Browser/download validation remains deferred.
